# 组件设计规范

目标：让组件“可复用、可维护、可测试”，避免随着工具数量增长而失控。

## 分层约束

- ui：纯展示/交互基础组件（不含业务、无网络、无存储）
- features：业务组件与页面（只做编排与交互，复杂规则下沉到 domain）
- domain：业务模型与规则（纯 TS，不依赖 uni/wx）
- services：对外部系统的访问（storage、cloud、feedback 等），必须可被 mock

## Props / Emits 设计

- props 尽量原子化（字符串/数字/布尔/函数），避免传入“巨型对象”导致耦合
- emits 统一使用动词短语（如 updateScore、submitFeedback）
- 任何影响外部状态的行为都通过明确事件触发，避免隐式修改父级数据

## 可测试性约束

- 页面内复杂逻辑必须抽到组合式函数或 domain/service
- 组件只保留与视图渲染和用户交互直接相关的最小逻辑

## 样式与响应式

- 优先使用 flex 布局与 rpx 单位
- 交互控件尺寸满足触控（按钮/点击区需足够大）
- 避免过度全局样式；公共样式统一沉淀到 ui 组件或全局主题文件
