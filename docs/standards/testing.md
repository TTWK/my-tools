# 测试规范（TDD）

## 测试分层（必须）

- 单元测试（unit）：domain 与纯函数/组合式函数，覆盖主要分支与边界条件
- 集成测试（integration）：service 与 store 的组合行为（mock 掉平台 API）
- E2E 测试：关键用户路径（新建对局 → 记分 → 查看历史 → 导出/同步）

## 编写顺序（TDD）

1. 根据 requirements 文档列出验收标准（Acceptance Criteria）
2. 为每条验收标准写测试用例（先失败）
3. 编写最小实现让测试通过
4. 重构（保持测试全绿）

## 约定

- 测试用例命名使用中文描述业务意图
- 每个测试文件保持聚焦：一个文件只覆盖一个模块/一个场景集合
- mock 必须集中管理（统一 mock 入口），避免各处散落导致维护成本暴涨
- 禁止依赖真实云端环境运行 unit/integration；E2E 允许依赖本地开发者工具
